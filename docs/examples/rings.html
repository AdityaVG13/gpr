concept · 01

Per-intent reading rings

As you scroll past each intent, its ring fills. The footer aggregates every intent's read-fraction into a single page-level "73% read" gauge. Reader sees attention coverage at a glance; author sees which sections everyone skips.

MechanicAn IntersectionObserver per intent samples viewport-time as you scroll. dwellMs / threshold drives stroke-dashoffset on the ring. Pure CSS animation, ~40 LOC of JS.

I002 · in progress

JWT auth flow with refresh-token rotation

Authentication splits into three concerns: issuance (short-lived access token), refresh (rotation on each use, with reuse-detection that revokes the entire family), and verification (constant-time signature check at every protected endpoint). Each one is a sub-intent in v0.2; for now we've landed issuance.

I003 · open

CRUD endpoints for the TODO resource

Five routes. GET / for list, POST / for create, GET /:id, PATCH /:id, DELETE /:id. Validation via Pydantic; ownership scoped by the JWT subject; pagination via cursor not offset; soft-delete with a deleted_at column rather than physical row removal.

I004 · open

Rate limiting on the auth endpoints

The login route is the front door for every credential-stuffing botnet on the open web. We cap to 10 attempts per IP per minute, with a 15-minute lockout after the cap is hit. Implementation lives in Redis with a sliding window; a fallback to in-memory for local dev.

I005 · open

Observability: structured logs and one health route

Every request produces a single JSON log line keyed by request_id. Health check at /healthz returns 200 with a tiny payload describing build sha, db reachable, redis reachable. No Datadog yet — that's an explicit anti-goal for v1; we ship plain stdout JSON and let the operator pipe it.

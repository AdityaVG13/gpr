Tufte sidenotes

Margin-anchored notes for verifyCmd rationale and decision context. On wide viewports they live in the right margin as siblings to the body; on narrow viewports they collapse to a checkbox-toggled inline reveal. Float + clear — never overlap, regardless of how many are open.

MechanicHTML structure is <label class="sn-toggle">¹</label><input class="sn-input" type="checkbox"><span class="sn">…</span>. Sidenotes float: right; clear: right; into a 280px reserved gutter; each one clears the previous so the column flows vertically without piling up. Pattern is verbatim Tufte CSS, MIT licensed.

What the rationale looks like in prose

Intent I002 implements JWT issuance with a 15-minute access token1Why 15 minutes? Anything shorter than 5 mins burns refresh-token round-trips on a chatty client; anything longer than 30 mins gives a stolen token enough runway to drain a session. 15 is the empirically common sweet spot — Auth0, Okta, and Clerk all default within ±5 of it. and a 7-day refresh token2Refresh tokens rotate on every use; reuse of an old refresh token is treated as a stolen-credential signal and revokes the entire token family for that user. Implementation borrowed from RFC 6819 §5.2.2.3.. The audit verifies issuance via pytest -k test_login_jwt3The check uses pytest because it's already in the project; using curl | jq would be more portable but would duplicate the test fixtures we'd need to spin up the auth context. Trade-off accepted. and refresh via the integration test in tests/test_refresh.py::test_rotation.

The negative constraint is explicit: the system must not store passwords in any form a developer's eyes can read. We hash with Argon2id at the registered OWASP parameters4OWASP 2024 recommendation: Argon2id with memory=65536 KiB, iterations=3, parallelism=4. We picked these over bcrypt because Argon2id resists GPU-based attacks meaningfully better and the memory cost defeats commodity ASIC rigs., and the column is named password_hash with no migrations that ever named it anything else.

Rate limiting510 attempts per IP per minute, 15-minute lockout. Sliding window. Redis-backed with an in-memory fallback for local dev so contributors don't need Redis to run the test suite. caps the login endpoint at 10 attempts per IP per minute. The check is a real timing test, not a unit test of the helper — we wait, we attempt, we expect 429.

Why this matters for a PRD

A PRD's hardest job is encoding why decisions were made. Margin notes survive into PR review without polluting the main narrative; they're optional reading for a stakeholder skimming the Goal section but available for the implementor who needs to know why I002/C2 uses pytest and not curl.
